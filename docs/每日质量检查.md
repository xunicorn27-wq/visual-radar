# 每日质量检查

新批次使用 `editorial-v2` 筛选策略。它只影响新日报，不重写历史期刊的评分或精选名单。

正式发送要求新策略日报。旧期可以浏览、回放检查和继续静态部署，但不能靠手动添加策略字段获得发送许可；应重新准备、解读并生成。`issue:quality` 的通过仅表示内容检查通过，不代表已部署或已获发送确认。

## 两层判断

- 原文证据：正文快照、事实摘录、来源 URL 和 contentHash 必须一致。
- 编辑推荐：`assessment` 区分内容类型（制作案例、作品、公告、商品汇总、趋势汇总、厂商案例）和方法证据（具体、笼统、没有）。公告、商品/趋势汇总不会因为事实正确就自动进入精选；厂商案例需要保留独立验证限制。

## 跨期事件

每条新核验内容填写稳定的 `event.key` 和简短 `event.label`。同一正文、同一 URL 或明确复用同一事件编号时，可合并为一个事件组并保留多条原文；只因品牌、人物或主题相似的条目不会自动合并，只会作为“疑似重复”提醒。

如果历史事件再次出现，必须填写 `event.development`，用本条已核验事实的 `factIndexes` 说明新增进展。换媒体、换标题或把同一事实改写一遍不算新进展。

`agent/prepare` 的 `eventCatalogue` 提供已刊编号与事实。旧期没有编号时使用 `legacy-<itemId>` 作为锚点，Agent 只有核对为同一事件才可复用。程序只验证引用关系和摘录未照抄，不能自动证明语义新颖性；该判断仍由编辑负责。未核验的旧文章没有足够事实基线，不能自动批准为“新增进展”。

实体相似提醒目前主要依据原文标题中的拉丁字母专名和14天期刊日期窗口，不是完整的多语言语义去重。历史回放使用入选期刊日期，避免滚动文章后来更新的发布日期干扰。没有提示也不代表没有重复；同一品牌的不同季节或项目必须使用不同编号。已确认重复在新日报中只保留一个主条目，其他原文列在“同一事件的其他原文”；已刊且无新增的内容会在“本次未重复推荐的已刊事件”保留链接。

## 发布前清单

管理区“发布前质量清单”或 `pnpm issue:quality YYYY-MM-DD --strict` 会输出：

- 阻塞项：空日报、任一正文解读未核验、身份/正文不匹配、重复正文、无效链接、无效日期或倒置展期、非真实采集、缺少新策略判断、精选低于阈值、重复旧事件但没有新进展。
- 提醒项：缺图、日期未注明、未来发布日期、疑似重复、评分过于集中、来源健康不适用当前期号、核心来源未覆盖。
- 推荐分层：普通参考（60–74）、精选候选（75–84）、高价值（85+）和低于60分；分层依据会显示在清单中，不静默改写历史分数。

只有阻塞项为零才允许 `publish:verify` 和企业微信发送。来源故障本身通常是提醒，不会把真实可核对的条目全部阻止；但它必须标明检查时间和覆盖范围。

清单是只读检查。不会采集、修改日报、发送企业微信或写入来源健康文件。

管理区仅在本地服务模式显示质量清单，需要输入管理密钥后点击读取。公开 Pages 不提供管理接口。来源覆盖由本次采集记录回放，不把后来的小范围探测当作全站检查，也不累计探测失败次数。

## Agent 输出示例（加在 editorial 内）

```json
{
  "assessment": {
    "contentKind": "production_case",
    "methodEvidence": "specific",
    "rationale": "原文描述两种实际使用的布光材料及其制作过程"
  },
  "event": {
    "key": "example-studio-light-study-2026",
    "label": "某工作室2026布光研究",
    "development": {
      "summary": "相较历史报道，本次新增具体材料与灯位方法",
      "factIndexes": [0]
    }
  }
}
```

没有旧报道时省略 development；不得为绕过重复拦截编造它。contentKind 可选：`production_case`、`artwork`、`announcement`、`product_roundup`、`trend_roundup`、`vendor_case`；methodEvidence 可选 `specific`、`general`、`none`。事件编号限 8–120 位小写字母、数字和连字符。

精选阈值75；公告/商品汇总/趋势汇总及笼统方法最多74；无方法最多59；厂商案例最多84；只有一条事实或较低来源质量最多79。分数以现有总分和这些上限中较低者计算，不降低底层原分、不补齐精选名额。网页和微信只使用实际选择的精选名单。
